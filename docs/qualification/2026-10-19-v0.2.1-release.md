## Results

### Exclusion (PR-01)

- **Invalid pattern:** `--exclude keep/sub` is refused with exit 1. No scan,
  no `run.json`, and nothing on the destination. (See finding 2: the work
  dir and its lock file are created.)
- **Copy:** run with `--exclude .snapshot --exclude '*.tmp' --exclude .zfs`.
  The fixture has `.zfs/` at the top and nested under `keep/sub/`, plus
  `build.tmp/` and `keep/sub/cache.tmp/`. The destination and the index hold
  exactly the kept entries. The files `file.tmp` and `keep/sub/notes.tmp` are
  copied, because files never match. `run.json` keeps the three patterns.
- **Sync:** new files under both kept and excluded directories, then a sync.
  Only `keep/new.txt` is copied.
- **Cutover:** passes, 7 entries.

### Cutover (PR-03)

**Fixture:**
- a 4 GiB file and two files of 256 MiB;
- 3,200 small files in 32 directories;
- a relative symlink and a dangling symlink;
- an empty file, an empty directory, and a 0700 directory owned by another
  user;
- an excluded `.zfs` subtree.

**Clean run:** the copy moved 4.94 GB, 3,244 entries, in 39 s, and the cutover
passed.

**Damage:** ten changes were then made on the destination after the last
sync:

| Damage | Reported as |
|---|---|
| 4 bytes overwritten in a file, same size | `content` (and `mtime`) |
| A file truncated | `size` (and `mtime`) |
| An extra file | `extra` |
| A file moved away | `missing` |
| A file replaced by a directory | `file_type` |
| A symlink pointed elsewhere | `symlink_target` |
| Mode changed | `mode` |
| Owner changed | `owner` |
| Mtime changed | `mtime` |
| One byte flipped at offset 3 GiB in the 4 GiB file | `content` (and `mtime`) |

The cutover exited 1 with 13 mismatches covering exactly the ten paths. The
baseline did not move, and the failed pass was kept. Once repaired, the
cutover passed again with 3,244 entries and 4.94 GB read back from both
servers.

### Alias overlap (PR-04)

Each refusal exited 1:

| Source | Destination | Refused because |
|---|---|---|
| server name | first address, path inside the source | "Same server: both names resolve to" the address |
| server name | name in upper case with `:2049`, path is the source's parent | "Same server: same host name" |
| server name | another address, the same path | "both names resolve to" that address |
| first address | another address, path inside the source | "a directory created under the destination root is visible through the source connection" |

- **The first three:** refused before any scan. The tree, read uncached, did
  not change.
- **The last:** caught by the mounted-identity probe, after the local scan
  and plan. It started no copy. Its whole footprint was the probe's MKDIR and
  RMDIR under the destination root: that directory's mtime and ctime moved,
  and no entry was added or left behind.
- **Allowed:** a sibling path on the same export, through another address,
  and the destination export on the same server. Both copied and passed
  cutover.

### Crash (PR-05, PR-06)

**Setup:**
- The source is a 19,281-entry tree of 1.75 GB.
- A non-empty directory sits on the destination where `d00/f0004.dat`
  belongs, so its publish fails.

| Kill (SIGKILL) | State afterwards | Rerun |
|---|---|---|
| Copy, after 4 of 32 shards, including the blocked file's shard | `progress.json` valid. The failure record for the blocked file (`EEXIST`, phase `rename`) is in that shard's `failures/` file. The stale `.mongoose.lock` is still there. | The copy resumes and exits 2 (1 failed) |
| Sync delta copy, after the blocker was moved aside and 1,920 files changed | Baseline unchanged | The sync retries the blocked file and copies it byte for byte; exit 0 |
| Cutover read-back | | The cutover resumes from its checkpoints |

**Cutover:** the resumed cutover exited 1 on two extras, both stale
`.partial` files:
- `d37/.f0221.dat.<client>.<pid>.partial` came from the killed sync.
- `d00/.f0004.dat.<client>.<pid>.partial` came from the copy's failed rename
  (finding 3).

`docs/REFERENCE.md` says an extra fails the cutover, "including … any stale
`.partial` file from an interrupted copy". Moved aside, as an operator would
remove them, the cutover passed: 19,281 entries, 1.75 GB.

### Concurrency (PR-06)

Two copies started together on one new work dir: one ran to completion (exit

### Torn copy (PR-07)

Six 1 GiB files were rewritten in place (3,564 writes of 4 KiB) while the copy
read them.

- **Copy:** reported `6 files ok (6 torn)` and wrote six `TORN_COPY` records,
  each with its pre and post (size, mtime, ctime).
- **Sync:** recopied all six with 0 torn.
- **Cutover:** passed, 6.44 GB read back.

On this server every write moves ctime, which cannot be set back, so the sync
saw these files as dirty. The "forced into the next sync even when its scan
tuple matches" path is therefore covered only by the software tests.

## Not run: scan error (PR-02)

The test needs a source directory the server refuses to list. On these
exports root is not squashed, so mongoose, which must run as root, can read
every directory. Scanning as another user through a libnfs `?uid=` option
fails at the scan (finding 1).

The project owner accepted this gap on 2026-10-19. Coverage stays with the
software tests: walker fault injection and the scan acceptance tests. A
root-squashed view over a directory with mode 000 would let a later release
run it.

## Findings

None of these risks data, and none blocks this release.

1. **A source URL with libnfs options fails at the scan.** For example,
   `nfs://server/export/path?uid=65534`: the walker passes the query string
   as part of the export path, so every mount fails and mongoose exits 1.
2. **An invalid `--exclude` leaves a work dir and lock behind.** The pattern
   is refused before any scan or `run.json`, but the work-dir lock first
   creates the directory and its `.mongoose.lock`. The man page says
   "refused before anything is written".
3. **A failed publish leaves its `.partial` behind.** When the rename onto
   the final name fails (here `EEXIST`, onto a non-empty directory), the
   partial file stays in the destination tree, and the cutover reports it as
   an extra until it is removed. The docs cover leftovers from interrupted
   copies, but not this case.
4. **The documented minimum gh version for verifying a release is too low.**
   `scripts/verify-release.sh` and `docs/BUILDING.md` say gh 2.49 or newer,
   but `gh attestation verify --source-ref` first appears in gh 2.68.0. With
   2.62 to 2.67, verification fails at the provenance step.
5. **Environment:** one copy's mount failed to resolve the server name.
   mongoose exited 1, and a rerun was clean.

## Reruns

Each test's final run is the one reported above. The earlier runs are in the
JSON record with their reasons. Every one was a fault in the harness, the
session, or the environment, never a product failure:
- **Fixture assumptions:** VAST's reserved `.snapshot`, and the index has no
  row for `/`.
- **Caching:** checks read through the cached kernel mount.
- **Broken checks:**
  - a check that read the wrong logs;
  - a plain-path match against `path_b64`;
  - a baseline check before any baseline existed;
  - a source-change loop that stopped early;
  - a variable clash in the container script;
  - a damage byte that matched the original.
- **Session and environment:** one session drop, and one transient DNS
  failure.
